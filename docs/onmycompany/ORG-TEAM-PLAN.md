## 0. 一句话

**企业管「有哪些队 + 公司有哪些人」；团队管「这个队里有谁」；账号先属于企业，再加入团队。**

```text
平台 (ops-admin)          ← 装机运维，员工不可见
└── 企业 (单 Org)
      ├── 企业超管 / 企业管理员 / 企业审计 / 员工     ← 企业账号层
      ├── 团队 A / B / C …                           ← 组织管理的对象
      │     └── 队所有者 / 队管理员 / 队成员         ← 团队里的管理者
      └── 策略 · 连接池 · Skills · 审计               ← 企业共享（连接 ACL 二期）
```

## 2. 角色定稿

### 2.1 平台层

| UI 名    | 实现                            | 说明                           |
| -------- | ------------------------------- | ------------------------------ |
| 平台运维 | `ops-admin` / `OMC_ADMIN_TOKEN` | 控制台解锁、落密钥；非业务角色 |

### 2.2 企业账号层（花名册 · 下拉三项）

| UI 名          | 代码      | 白话                     | 能力                                                |
| -------------- | --------- | ------------------------ | --------------------------------------------------- |
| **企业管理员** | `admin`   | 公司管家人               | 花名册 CRUD、建队、企业设置、全公司视图、审计       |
| **企业审计**   | `auditor` | **只看不改**（合规旁观） | 审计/用量/运行全量只读、全公司视图；不能改人/改配置 |
| **员工**       | `member`  | 普通同事                 | 登录、入被分配的队、自己的执行与用量                |

**企业超管**：不单独做 `owner` 字段；= bootstrap 首个 `admin` + **不可停用/删除最后一个 admin**（已实现）。

### 2.3 团队层（membership）

| UI 名          | 代码           | 能力                                       |
| -------------- | -------------- | ------------------------------------------ |
| **团队所有者** | `creator`      | 建队人；不可降级/移出（已有）              |
| **团队管理员** | team `admin`   | 本队加人（从企业账号池）、改队角色、改队名 |
| **团队成员**   | team `member`  | 本队协作                                   |
| 团队观察者     | team `auditor` | **P2 再赋权**；P0 可不展示                 |

**规则**

1. 同一人可：企业 `member` + 某队 `admin`。
2. 先有**企业账号**，再**入队**。
3. **停用企业账号** → 全队失效；**移出团队** → 只出本队。
4. 企业管理员可操作任意队；团队管理员仅本队。

## 3. 信息架构定稿（P0 核心）

### 3.1 侧栏（已落地：团队合并为一项）

```text
工作台
  概览              /overview
  应用连接          /connections
  企业账号          /members
  团队              /team          ← 侧栏仅一项
      · 具体队 → /team?team=…
      · 全公司 → /org/teams（全部团队，不进侧栏）
配置
  企业设置          /org-config
```

**文案强制**

| 禁止（易混）                | 使用                                            |
| --------------------------- | ----------------------------------------------- |
| 组织管理 / 组织配置         | **企业设置**                                    |
| 成员管理（两层都叫成员）    | **企业账号** vs **团队成员** / 本队成员         |
| 侧栏并排「团队列表 + 团队」 | 侧栏只 **团队**；列表走全公司或页内「全部团队」 |
| 可使用连接=默认可用         | 有 ACL 前不展示假 ACL                           |

### 3.2 页面职责（互不抢活）

| 页面                       | 管什么                                 | 不做什么                 |
| -------------------------- | -------------------------------------- | ------------------------ |
| **企业账号** `/members`    | 邮箱、显示名、企业角色、启停、删除     | 队内角色、建队           |
| **全部团队** `/org/teams`  | 有哪些队、创建、点进某队               | 停用企业账号（不进侧栏） |
| **本队成员** `/team`       | 本队名单、队内角色、从账号池拉人、移出 | 改企业角色、停用账号     |
| **企业设置** `/org-config` | 策略、模型目录、Skills 启用            | 管人                     |

### 3.3 工作上下文切换器（左下）

- 选项：`全公司`（仅企管/审计）| 各队
- 作用：计量/运行/概览的默认 `teamId`；**不是**主管理入口
- 「管理」→ `teamNavTarget`：全公司进 `/org/teams`，否则本队成员
- 本队页提供 **全部团队** 链到 `/org/teams`

### 3.4 加人两条路径（必须分清）

| 场景       | 入口                          | API                                                         |
| ---------- | ----------------------------- | ----------------------------------------------------------- |
| 公司来新人 | 企业账号 → 添加               | `POST /api/org/members`                                     |
| 拉进某队   | 团队成员 → 添加（从账号池选） | `POST /api/teams/:id/members`（可自动建账号但 UI 文案写清） |

## 8. 风险与对策

| 风险                         | 对策                                                 |
| ---------------------------- | ---------------------------------------------------- |
| 用户仍把「成员」「团队」搞混 | 文案强制表 §3.1；空态写「先开企业账号，再入队」      |
| 历史 run 无 teamId           | 全公司可见；单队过滤说明「仅统计带团队标记的调用」   |
| 本地双登录                   | 已有 `ensureMemberSessionForConsole`；生产依赖真 OTP |
| 范围膨胀到 ACL               | Phase 3 单独排期，不阻塞 Phase 1 发布                |

---

## 9. 默认决策（你未反对即按此开工）

1. **单企业**，不做多 org。
2. **企业超管** = 首 bootstrap admin + 不可删最后一个 admin（P2 再引入显式 `owner`）。
3. **导航** = 企业账号 + **团队**（侧栏一项）+ 企业设置；全部团队 = `/org/teams`（全公司 / 页内入口）。
4. **连接** Phase 1 企业共享；ACL 放 Phase 3。
5. **普通员工** 可见自己所在队的成员表（只读写权限由 API 收紧）。
