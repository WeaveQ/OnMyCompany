# 员工与桌面

员工在 OnMyAgent 里办公。OnMyCompany 管理台没有「新对话」，也不托管工作区。

产品入口（桌面）：**设置 → 工作区 → 公司**。连上并同步成功后，主栏才会出现 **企业**。

更细的桌面操作以 OMA 手册为准：[企业连接](https://weaveq.github.io/OnMyAgent/docs/guide/company)。

## 1. 本地模式和企业模式

|             | 未连接                | 已连接                               |
| ----------- | --------------------- | ------------------------------------ |
| 要不要登录  | 不要                  | 要企业地址 + 成员会话                |
| 配置        | `profiles/local`      | 同步成功后用 `profiles/company` 镜像 |
| 策略        | 产品默认和本机选择    | 组织策略；桌面不得放宽               |
| 技能 / 专家 | 本机安装或自建        | 另可读组织目录（通常只读）           |
| 凭据        | 自己的 BYOK           | 公司 Gateway 密钥不回桌面            |
| 企业 HTTP   | 无 BaseUrl 时必须为零 | 仅在已配置地址后发生                 |

可以随时切回 local（契约 B1）。公司宕机时，本机模式仍应能用。

## 2. 连接步骤

管理员先把该邮箱加进 **企业账号**，最好再拉进一个团队。

1. 打开 OnMyAgent → **设置 → 工作区 → 公司**。
2. 填组织地址，例如 `http://127.0.0.1:3100`。用内网正式部署时换成管理员给的 URL，端口以实际 `PORT` 为准。
3. 企业邮箱 + 验证码。本地固定码默认 `000000`。
4. 等技能、专家、模型目录、Gateway 目录、策略同步。
5. 回主界面，确认 **企业** 入口出现。
6. 要改组织人、策略、连接：打开管理台，不要在桌面另做一套。

可用管理台或 `GET /api/company/health` 探活。不要在录像里展示域名、邮箱、验证码、token。

## 3. 连上之后应看见什么

| 应看见       | 说明                          |
| ------------ | ----------------------------- |
| 组织 Skills  | 仅当前企业角色可见的包        |
| 组织专家     | 管理员启用过的人设包          |
| 模型目录     | 指向 OmniRoute，没有 API Key  |
| Gateway 服务 | 已配置的办公连接；没有 secret |

对话模型仍走 OmniRoute（桌面侧的 Base URL / 路由）。工具应走公司 `/v1` 或 `/mcp`，并带该成员的 runtime token。被拒绝时读返回文案：策略、队授权或工具次数配额。模型 token 超限是 Omni 的事。

**不会看见：** 浏览器里的公司聊天、模型 Key、别人的个人技能。

## 4. 当前桌面边界（诚实）

服务端这些接口已经在：探活、登录、`/me`、拉配置、生效策略、铸造 runtime token、`/v1`、`X-Team-Id`。

桌面 2b 已落地：公司地址与会话持久化（`~/.onmyagent/company-settings.json`）、配置镜像、设置页最小路径。

仍不要按「全链路已强制」对外讲：

- 每次工具调用都走公司网关（`gateway_required` 全 runtime）未满
- 桌面是否每次都铸造 token、都带 `X-Team-Id`、拒绝文案是否完整，以当前 OMA 版本为准
- 没有企业工作台或审批队列主路径

管理员把本页或 [MEMBER-ONBOARDING.md](/onmycompany/MEMBER-ONBOARDING) 发给同事即可。

## 5. 断开与排障

| 现象                     | 检查                                                                       |
| ------------------------ | -------------------------------------------------------------------------- |
| 无法连接                 | 地址是否指向 API 而不是 `:5180`；`/health`；邮箱是否已入册；验证码是否过期 |
| 登录成功但没有企业入口   | 配置 pull 是否完成；会话是否还在                                           |
| 目录是空的               | 组织是否发布了 Skills / 专家；可见角色是否包含该员工                       |
| 看得到但不能用           | 企业设置策略、连接是否禁用、队授权、配额                                   |
| 断开后仍看到旧目录       | 已切回 local；镜像保留不等于还连着                                         |
| 未填公司地址却有企业请求 | 视为桌面缺陷（D1），应报给 OMA                                             |

登出后桌面回到本地模式，不得再打企业 HTTP。镜像目录可以留在磁盘，但不能再当实时真相。
