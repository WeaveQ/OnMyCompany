# 连接器与网关

连接器是企业共享的办公应用连接池。Agent 通过公司 Gateway 的 `/v1` 或 `/mcp` 调用，密钥留在公司进程。

产品入口：侧栏 **连接器** `/connections`。配置密钥进 **提供商** `/providers/:service`。调试单个 Action 进 **操作** `/actions`（不进侧栏）。

## 1. 和「…」有什么区别

|              | 连接器                                       | 桌面本机连接         | OmniRoute          |
| ------------ | -------------------------------------------- | -------------------- | ------------------ |
| 管什么       | GitHub、飞书、邮箱等工具出口                 | 未连公司时的个人钥匙 | 对话模型厂商与 Key |
| 密钥在哪     | 公司服务器                                   | 本机                 | Omni 进程          |
| 谁写         | 平台运维（密钥）；企业管理员可启停、按队授权 | 员工自己             | 模型管理员         |
| 员工看见什么 | 已配置、无 secret 的目录投影                 | 本机设置             | 推荐模型列表       |

## 2. 从哪里打开

1. 侧栏 **连接器**：浏览 office 目录、按状态 / 分类筛选。
2. 点某个服务的连接或管理：进入提供商页，填写 API Key 或 OAuth。
3. 行内 **操作**：打开该服务的 Action 列表，可在控制台试跑（调试用）。
4. 页面下方 **Connection team grants**：给已配置服务填允许使用的团队 id。

## 3. 界面结构

连接器列表：

| 区域               | 作用                                               |
| ------------------ | -------------------------------------------------- |
| 搜索 / 排序        | 推荐或按名称                                       |
| 状态               | 全部 / 已配置 / 需要处理 / 可直接使用（`no_auth`） |
| 分类               | AI、效率、沟通、文档、开发工具等                   |
| 提供商目录（高级） | 完整提供商页，开发调试用                           |
| 按队授权卡片       | 已配置服务 → 团队 id 列表                          |

默认 catalog 是 `OMC_CATALOG_PROFILE=office`，大约 70 个办公相关服务，不是上游 1000+ 全表。改全量是部署变量，管理台没有开关。

提供商页可以给同一服务建多个命名连接（如 `default` / `work` / `prod`）。执行时按主备顺序尝试（G1a）：可重试错误会切到下一个，并在运行记录里留下 `fallback` / `connectionName`。

## 4. 能做什么

| 操作                        | 谁               | 说明                                              |
| --------------------------- | ---------------- | ------------------------------------------------- |
| 浏览目录                    | 已解锁控制台的人 | 不回显密钥                                        |
| 保存 API Key / OAuth 客户端 | 运维控制台会话   | 密钥只写一次，再打开看不到明文                    |
| 断开连接                    | 运维             |                                                   |
| 启停组织连接                | 企业管理员       | 禁用后执行报 `connection_disabled`                |
| 按队授权                    | 企业管理员       | 空名单 = 不限制；非空名单必须带匹配的 `X-Team-Id` |
| 试跑 Action                 | 运维调试         | 仅 `locallyExecutable` 的项能 Run                 |

无鉴权服务（如 Hacker News、部分学术源）标成「可直接使用」，不必先填密钥。

## 5. 使用建议

1. 试点只开真正要用的几个服务，再靠企业设置的允许列表收口。
2. 生产环境先设 `OMC_ENCRYPTION_KEY` 再写真实密钥。
3. 同一服务要主备时，用不同 `connectionName`，不要复制一份到每个团队。
4. 按队授权不是「每队一把私有钥匙」。没有授权行或名单为空：谁都能调，`X-Team-Id` 可选（不带头则 run 没有队归因）。名单非空：必须带匹配的 `X-Team-Id`，缺头或队不在名单里都是 `403` `connection_team_denied`。

## 6. 常见状态

| 状态               | 含义                               | 建议                                                                  |
| ------------------ | ---------------------------------- | --------------------------------------------------------------------- |
| 可直接使用         | 无需鉴权                           | 可直接 `/v1` 试                                                       |
| 需要处理           | 未配齐或 OAuth 未完成              | 打开提供商页                                                          |
| 已配置但仍 403     | 策略禁止、连接被禁用、或队授权拒绝 | 看拒绝码：`policy` / `connection_disabled` / `connection_team_denied` |
| 429 `rate_limited` | 打到全局或每人并发帽               | 等 `Retry-After`；默认全局 100、每人 10                               |
| 目录里没有某应用   | office 画像未收录                  | 运维设 `OMC_ALLOWED_SERVICES` 或 `full`，不要指望界面切换             |

OAuth 回调依赖 `OMC_ORIGIN`（本地一般是 `http://127.0.0.1:3100`）。飞书等国内应用的**生产换票**仍可能是 stub，连上授权页不等于生产可用。
