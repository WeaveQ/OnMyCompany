# 计量、运行与审计

观测分成三本账，不要混着看。

产品入口：侧栏 **计量计费** `/metering`、**运行记录** `/runs`、**审计事件** `/audit-events`。概览也有用量摘要。

## 1. 三张表

| 页       | 记什么                                                  | 不记什么        |
| -------- | ------------------------------------------------------- | --------------- |
| 计量计费 | 经 Gateway 的工具次数；另页签代理 Omni 的 LLM 用量      | 发票、预扣费    |
| 运行记录 | 每次 Action 的成败、连接名、fallback、memberId / teamId | 登录、改花名册  |
| 审计事件 | 登录、改人、改配置、token、连接启停、策略拒绝、Skills   | Action 输出正文 |

## 2. 计量计费

需要成员会话。页内没有登录卡时，会把你送到团队页去登录。

三个页签：

| 页签 | 内容                                                                 |
| ---- | -------------------------------------------------------------------- |
| 用量 | 工具 KPI、按日、按服务；LLM 请求数 / token / 估算费用（无 memberId） |
| 日志 | 公司侧 Gateway 调用日志，受顶栏团队切换器过滤                        |
| 价格 | 参考价。LLM 尽量来自 Omni，工具价在本地。响应带 `source`             |

切换器打在某队时，工具用量带 `teamId`。全公司（企业管理员 / 审计）不过滤队。

LLM 数字没有员工归因。不要用它做「谁在烧模型」。

价格是参考目录，不是对账单。商业预扣、OpenMeter、Lago 默认不做。

## 3. 运行记录

这是 Gateway 执行历史，控制台解锁后就能看列表。

| 能做                                    | 说明                           |
| --------------------------------------- | ------------------------------ |
| 筛 Action / 服务 / 成员 / 调用方 / 状态 |                                |
| 展开结果 JSON                           | 注意不要把敏感输出贴到别处     |
| 导出 JSONL / CSV                        | 需要企业管理员或审计的成员会话 |

字段里和主备、归因有关的：`attempt`、`fallback`、`connectionName`、`memberId`、`teamId`。没带 `X-Team-Id` 的 run，`teamId` 为空，按队看会漏。

普通员工在产品口径上只应看到自己的执行。审计和管理员看全量。

## 4. 审计事件

控制面操作日志。API 要求企业管理员、企业审计，或运维 cookie。普通员工不要当自己的时间线。

| 能做                                   | 说明                              |
| -------------------------------------- | --------------------------------- |
| 按类型、操作者、客户端、关键字、时间筛 |                                   |
| 日期快捷                               |                                   |
| 导出 CSV                               | 导出本身会再记一条 `audit.export` |
| 翻页                                   | 每页 50                           |

事件含摘要、客户端、IP。导出不含连接密钥。

## 5. 使用建议

1. 「工具有没有打出去」看计量和运行记录。「谁改了策略 / 谁登录失败」看审计。
2. 查某次拒绝：审计里的 `policy.deny` 加上运行记录里的失败行，对照企业设置。
3. 给合规导出审计即可，不必把 Action 结果 JSON 整包外发。

## 6. 常见状态

| 状态                               | 含义                 | 建议                     |
| ---------------------------------- | -------------------- | ------------------------ |
| 计量让你去 `/team`                 | 没有成员会话         | 先验证码登录             |
| LLM 页失败                         | Omni 没开或探活失败  | 开边车，或只看工具账     |
| 按队看不到某次调用                 | 当时没带 `X-Team-Id` | 全公司视图里找「未归属」 |
| 员工打开审计 403                   | 角色不够             | 换审计或管理员           |
| 概览「策略拒绝」和清单完成态对不上 | 开局清单完成条件偏松 | 以审计和运行记录为准     |
