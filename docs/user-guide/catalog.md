# Skills、专家包与模型

组织把技能包、人设包和「推荐模型目录」下发给桌面。公司管理台只发布和启停，不在浏览器里跑对话。

产品入口：侧栏 **Skills** `/skills`、**专家包** `/experts`。模型主路径是侧栏外链 **模型路由**（OmniRoute dashboard）。

## 1. 和「…」有什么区别

|                | Skills                           | 专家包                   | 模型目录                    |
| -------------- | -------------------------------- | ------------------------ | --------------------------- |
| 是什么         | 可安装的能力说明 / 包            | 岗位人设包               | 给桌面看的模型列表          |
| 员工怎么用     | 在 OnMyAgent 会话里当技能        | 在桌面专家栏对话         | 选模型，Key 不在桌面        |
| 公司端能做什么 | 关联、上传、设可见角色、分享链接 | 启用 / 移除              | 探活 Omni；不要在本台填 Key |
| 不是什么       | 不是控制台里的「运行技能」       | 不是公司页里的聊天机器人 | 不是第二套模型后台          |

## 2. Skills

打开 **Skills**。未登录会先走成员验证码。

企业管理员可以：

| 操作                 | 说明                                                        |
| -------------------- | ----------------------------------------------------------- |
| 从货架添加           | 公开或「我的」货架，关联到组织                              |
| 上传 Markdown 或 zip | zip 里要有 `SKILL.md`。上传先落到个人货架，可选同时关联组织 |
| 可见角色             | `admin` / `member` / `auditor` 多选。空 = 所有角色          |
| 分享                 | 生成带 `shareToken` 的只读链接，不是对外商店上架            |
| 移除                 | 取消组织关联 / 删除包                                       |

普通成员只能看自己角色可见的列表。把可见角色设成仅 `admin` 后，员工的组织目录里不应再出现该包。

这里没有技能编排画布，也没有「点一下就跑」。跑在桌面会话里。

## 3. 专家包

打开 **专家包**。文案写明：下发给桌面的人设包，公司端不提供对话。

| 操作                     | 谁         | 说明                               |
| ------------------------ | ---------- | ---------------------------------- |
| 浏览 available / enabled | 已登录成员 |                                    |
| 启用                     | 企业管理员 | 写入 OrgConfig `experts/installed` |
| 移除                     | 企业管理员 | 只是组织不再下发，不是删桌面本机包 |

启用后，`GET /api/org/config` 里的 experts 应与桌面 `profiles/company/config` 镜像一致。不要在本页找「新对话」。

## 4. 模型

对话不经过 OnMyCompany 默认路径。

| 在哪配                                                         | 配什么                                                 |
| -------------------------------------------------------------- | ------------------------------------------------------ |
| OmniRoute dashboard（默认 `http://127.0.0.1:20128/dashboard`） | 厂商、API Key、路由、模型 token 限额                   |
| 概览 / 企业探活                                                | `modelRouter.ok` 探活                                  |
| 企业设置里的 models JSON                                       | 给桌面的推荐目录，**不含 Key**。页上写明这不是模型后台 |
| 计量 → LLM                                                     | 从 Omni 拉用量，没有 memberId                          |

本地另开边车：

```bash
npm run dev:omniroute
```

员工在桌面看到的组织模型应指向 OmniRoute，而不是让每人再贴一份公司 Key。是否允许个人 BYOK，由企业设置里的开关决定，见 [策略](./policy.md)。

## 5. 使用建议

1. 先发 1 个组织 Skill 和（如需要）1 个人设包，再叫员工连公司，便于确认镜像是否同步。
2. 按角色收可见性，不要指望「不上架别人就看不见」却把可见角色留空。
3. 模型 Key、模型配额只进 Omni。工具调用次数配额进企业设置，两本账不要合成一张发票。

## 6. 常见状态

| 状态                 | 含义                              | 建议                                            |
| -------------------- | --------------------------------- | ----------------------------------------------- |
| 暂无组织 Skills      | 还没关联                          | 管理员添加或上传                                |
| 成员看不见某包       | `visibleToRoles` 未包含其企业角色 | 改可见性                                        |
| 专家包列表空         | 货架里没有可启用的包              | 不要把这页当聊天入口                            |
| 概览模型路由失败     | Omni 没启动或地址不对             | `npm run dev:omniroute`；看 `OMC_OMNIROUTE_URL` |
| 企业设置里模型数为 0 | 目录未写                          | 不影响 Omni 本身是否可用                        |
